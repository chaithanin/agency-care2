The rule that governs everything here — disturb the existing workflow as little as possible

This requirement is a restructure, not a rewrite. More than half of what it asks for already exists in the system people use every day. The correct job is to extend what is there, not to stand up a parallel set of tables beside it.

Add, never alter New columns and tables are fine. Never drop a column or change what an existing one means.
Keep old routes alive A page that is folded away redirects, it is not deleted. People have it bookmarked.
Config before code Anything the config tables already handle (deal_stages) must not be hard-coded.
One phase at a time Five phases, one PR each. A phase ships to production before the next one starts.

SIX BUSINESS QUESTIONS THAT MUST BE LOCKED BEFORE THE DATABASE IS TOUCHED

All six are now settled. The commission basis was decided by the owner: Net Price = Sale Price − Discount − Promotion value, with no tax deducted.

QuestionProposed answerWhyState
1. When is a Sold Deal created?An authorised approver confirms the sale and the mandatory fields are complete — not the deposit aloneIf the deposit is the only trigger there is nowhere to hold the contract, payment schedule or commission before the customer pays — a circular dependencyAnswer proposed
2. Is Deposit a condition or a status?A status on one row of the payment schedule, not a condition for the deal to existThis keeps Booking, Contract, Down Payment, Installment and Transfer in one tableAnswer proposed
3. What is commission calculated on?Answered: Net Price = Sale Price − Discount − Promotion value. Tax is not deducted. basis is still stated per entry, because the agency rate runs on Sale Price.Needs a new bookings.promotion_value column — today promotion is free text and carries no numberAnswer proposed
4. What does Quota mean?Already answered: Ownership Quota. Use the live values in bookings.quota_categoryThai Quota · Thai Company · Foreign Quota · Sub-Ing-Sis · Lease-hold — real data exists, do not invent a new listAnswer proposed
5. One visit record or several?office_visits is the source of truth. visit_plans stays for planned field visits.Visit Summary and Site Visit Report become views over one data set, not a second data setAnswer proposed
6. Where does Agency Last Visit come from?MAX(office_visits.visit_at, visit_checkins.checkin_at) — computed, never entered by handThe moment there is a field to type it into, the number is wrong for every agency someone forgotAnswer proposed

BUILD ORDER — set by the owner, do not reorder

1. Business Rule→2. Data Model→3. Workflow / State→4. Information Architecture→5. Wireframe→6. UI Design→7. API→8. Development→9. Migration→10. UAT
Starting from Figma or the front end means rebuilding several times over. The six questions above must be locked before the database or the API is touched.

EIGHT THINGS A DEVELOPER MUST NOT DO — set by the owner as technical guardrails

1 Never merge Holding + Reservation by renaming a string and nothing else
2 Never relabel Closed Deal as Sold Deal and call the job done
3 Never build Deposit or Commission as free-text fields
4 Never make Visit Summary a second copy of the data
5 Never let Agency Last Visit be typed in by hand
6 Never delete history to solve a navigation problem
7 Never hard-delete a financial transaction
8 Never let an edit to the payment plan master change an existing deal
